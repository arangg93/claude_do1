## STEP 4 — 카카오톡 나챗방 발송

⚠️ **`KakaotalkChat-MemoChat` 도구는 메시지당 최대 200자다.** 초과하면 실패한다.

**기사 링크를 반드시 포함한다.** 다만 URL 하나가 40~50자를 먹기 때문에, 한 메시지에 **항목 2건**까지만 담긴다. 그래서 **6개 메시지로 나눠 순차 발송**한다. 각 메시지는 **190자 이내**로 맞춘다(한글·이모지·URL 전부 포함해서 센다. 애매하면 제목을 줄인다).

한 항목의 기본 단위는 **제목 한 줄 + URL 한 줄**이다:

```
①(제목 20~25자)
(URL 원문 그대로)
```

**메시지 1 — 헤더 + 입시 1·2**
```
📌8/16(일) 아침브리핑 🎓입시
①수능 원서접수 8/24~9/4, 사전입력 8/20
https://...
②수시 접수 9/7~9/11, 대학 자율 3일
https://...
```

**메시지 2 — 입시 3·4** / **메시지 3 — 입시 5 + 💼1인기업 1**
**메시지 4 — 💼1인기업 2 + 🤖AI 1** / **메시지 5 — 🤖AI 2·3**

주제가 바뀌는 자리에는 해당 이모지 머리표(`🎓입시` `💼1인기업` `🤖AI`)를 붙여 구분한다.

**메시지 6 — 마무리**
```
⚠️가장 급함: (임박한 마감/일정 한 줄)
🎯오늘 할 일
· (실행 항목 1)
· (실행 항목 2)
상세 요약은 메일 확인 📧
```

**규칙:**
- **URL은 단축하거나 변형하지 않고 원문 그대로** 넣는다. 카카오가 자동으로 링크를 인식한다
- URL 앞뒤로 다른 글자를 붙이지 않는다. **URL은 반드시 독립된 줄**에 둔다 (붙이면 링크 인식이 깨진다)
- 제목이 길어 200자를 넘길 것 같으면 **제목을 줄인다. 링크를 빼지 않는다** — 조사·수식어부터 버린다
- 요약과 "현장 함의"는 여전히 이메일 몫이다. 카카오에는 제목·링크·액션만 담는다
- 각 발송 후 성공을 확인하고 다음 메시지를 보낸다
- 항목이 10건보다 적은 날은 메시지 수도 그만큼 줄인다 (빈 메시지를 만들지 않는다)

## 지켜야 할 것

- **검색을 실제로 한다.** 뉴스를 지어내는 것은 이 스킬의 최악의 실패다
- **링크는 검색 결과에 실제로 있던 URL만 쓴다.** URL을 추측해서 만들지 않는다
- **날짜를 확인한다.** 몇 달 지난 기사를 오늘 뉴스로 보내지 않는다
- **"현장 함의"에 빈 말을 쓰지 않는다.** 쓸 말이 없으면 그 기사는 애초에 뽑지 말았어야 한다

## STEP 6 — 발송 전 한국어 검사 (필수, 건너뛰지 말 것)

사용자가 명시적으로 요청한 사항이다. **이메일과 카카오 본문을 쓴 뒤, 보내기 전에 반드시 아래를 확인한다.**

### 쉬운 말로 쓴다

- **한 문장은 짧게.** 한 문장에 주장 하나만 담는다
- **일상에서 쓰는 단어만 쓴다.** 어려운 한자어·문어체·조어를 만들지 않는다
- 아래처럼 쓰지 않는다 (실제로 발생한 오류다):

| 쓴 것 (뜻 안 통함) | 써야 할 것 |
|---|---|
| 문의가 **즐상**한다 | 문의가 **급증**한다 |
| **이토직의 차사수** | **이탈자·차순위 지원자** |
| **여드렛샐** | **여드레** |
| 제시문기반은 **준법**이 다르다 | **준비 방법**이 다르다 |
| 내년 8월 **곧** 지도 자료 | **고3** 지도 자료 |
| 가장 효율이 **다섯다다** | 가장 **확실하다** |
| **부론**으로 담지 않았다 | **본문**에 담지 않았다 |
| **유이한** 절차 | **유일한** 절차 |
| **쓸모**가 있다 | **쓸 데**가 있다 |

### 보내기 전 점검 항목

1. **본문을 처음부터 끝까지 다시 읽는다.** 뜻이 통하지 않는 낱말이 하나라도 있으면 고친다
2. 뜻이 애매한 낱말은 **더 쉬운 낱말로 바꾼다** (고민되면 무조건 쉬운 쪽)
3. HTML 태그가 깨지지 않았는지 확인한다 (`</ubc45>` 같은 잘못된 닫는 태그가 실제로 들어간 적이 있다)
4. 숫자·날짜·대학명을 원문과 다시 맞춘다

### 보낸 뒤 확인

- 발송 후 **Gmail `get_message`로 실제 도착한 메일 본문을 열어 읽는다** (`messageFormat: PLAIN_TEXT`)
- 깨진 낱말이 발견되면 **정정본을 다시 보내고** 사용자에게 알린다
- 사용자 보고 문단도 같은 기준으로 쉬운 말로 쓴다

## STEP 7 — 글자 깨짐의 진짜 원인과 대책 (2026.09.18 확인)

### 원인

파일에 쓴 본문은 깨끗했는데, **그 본문을 발송 도구의 인자로 다시 옮겨 적는 단계에서 깨졌다.**
즉 글을 짓는 단계가 아니라 **옮겨 적는 단계**가 문제다.
그리고 **글이 길수록 많이 깨진다.** 짧은 카카오 메시지는 거의 깨지지 않았다.

실제 확인된 사실:
- 긴 이메일 본문(8천 자)을 한 번에 보냈을 때 낱말 25개 이상이 깨졌다
- 같은 날 짧은 카카오 메시지(100자 안팎)는 깨지지 않았다
- **정정 목록을 이메일로 보냈더니 그 정정 목록까지 깨졌다.** 화살표 오른쪽(고친 말)이 또 틀렸다

### 대책 (반드시 이 순서로)

1. **카카오톡을 먼저 보낸다.** 한 메시지 120자 안팎으로 짧게 나눈다. 여기가 가장 안전하다
2. **이메일도 짧게 나눠 보낸다.** 한 통에 다 넣지 않는다. 주제별로 2~3통으로 쪼갠다
3. 발송 전 파이썬으로 각 메시지를 출력해 눈으로 읽고 글자 수를 확인한다
4. 발송 후 `get_message`로 확인한다
5. **깨짐이 발견되면 정정 목록을 이메일로 보내지 않는다.** 정정 목록도 깨진다.
   대신 **짧은 카카오 메시지로 핵심만 다시 보낸다**

### 절대 하지 않을 것

- 긴 한국어 본문을 한 번에 발송 도구에 옮겨 적기
- 깨진 것을 긴 글로 설명하려 하기
- 사용자에게 "확인했습니다"라고만 말하고 실제로 열어보지 않기

## STEP 8 — 이메일은 반드시 HTML 형식으로 (사용자 지시, 2026.09.18)

### 사용자가 직접 지시한 사항

> "예쁜 형태의 이메일을 다시 보내봐. 그냥 텍스트만 오는데.. 이거 노노."

**이메일은 항상 `body_type: html`로 보낸다. `plain`으로 보내지 않는다.**
글자 깨짐을 피하려고 서식을 버리는 것은 잘못된 해결이었다. **서식은 지키고, 글을 줄여서 해결한다.**

### 해결 방법 (2026.09.18 실제로 성공한 방식)

깨짐의 원인은 글의 **길이**였다. 서식이 아니었다.

- 실패: 긴 본문(항목마다 6~10줄) + HTML -> 낱말 25개 이상 깨짐
- 실패: 긴 본문 + plain -> 똑같이 깨짐 (서식과 무관)
- **성공: 짧은 본문 + HTML -> 깨짐 없음**

그래서 규칙은 하나다. **HTML은 그대로 쓰고, 각 항목의 글을 짧게 쓴다.**

### 항목 하나의 분량 상한

| 줄 | 분량 |
|---|---|
| 제목 | 한 줄 |
| 요약 | **2~3문장까지.** 그 이상 쓰지 않는다 |
| 할 일 | **1~2문장까지.** 그 이상 쓰지 않는다 |
| 출처 | 매체명 + 링크 한 줄 |

설명을 더 하고 싶으면 **참으라.** 길게 쓰면 깨져서 아무것도 전달되지 않는다.
자세한 배경은 사용자 보고 문단(채팅)에서 말한다.

### 서식은 이 골격을 쓴다 (2026.09.18 성공한 형태)

- 제목: `<h1>` + 아래 `border-bottom:3px solid #2d5f9a`
- 급한 마감: 빨간 상자 `background:#fdeaea; border-left:5px solid #c0392b`
- 주제 머리: `<h2>` 색 띠 — 입시 `#2d5f9a`, 1인기업 `#0f7b6c`, AI `#7c3aed`
- 항목: `border-bottom:1px solid #e5e5e5; padding:14px 0`
- 할 일 상자: 입시 `#fff8e1`, 1인기업 `#e8f5f2`, AI `#f3ebff`
- 보정·정정 상자: `background:#eef4ff`
- 다가오는 일정: 파란 상자 `background:#f5f8fc; border-left:5px solid #2d5f9a`
- 맨 아래: `border-top:2px solid #ddd` + 회색 작은 글씨

### 순서

1. HTML 본문을 짧게 쓴다 (위 분량 상한을 지킨다)
2. 보낸다
3. `get_message`로 열어 낱말을 확인한다
4. 깨진 곳이 있으면 **그 항목만 줄여서 전체를 다시 보낸다** (정정 목록을 보내지 않는다)
5. 카카오톡은 별도로 짧게 나눠 보낸다
